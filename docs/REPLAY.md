# 时间重放（Replay）施工文档

> 目标：把「关系网络怎么长出来的」做成能按月回放的东西。数据全部来自本地库，不联网、不调模型。
>
> 本文是施工前的规格，含**探测到的真实数据形状**。所有数字来自 2026-10-25 对当前库的一次扫描。

---

## 1. 要做什么

一条命令，按月回放：

```
weflow-cli replay                 # 文本：每月一段，看数字与断边
weflow-cli replay --out out.html  # 动画：按播放键，看边长出来
```

**核心看点不是"图变大了"**（那只是数据变多），而是**边断掉、边新长出来**。

---

## 2. 数据现实（先看这个，它决定了设计）

扫描结果：**32 个月（2024-03 ~ 2026-10）**，但有三个阶段：

| 阶段 | 月份 | 每月会话数 | 每月消息 | 说明 |
|---|---|---|---|---|
| 稀薄期 | 2024-03 ~ 2025-08（17 个月） | 1 ~ 2 | 7 ~ 695 | 几乎只有一两个会话 |
| 完整期 | 2025-09 ~ 2026-10（14 个月） | 42 ~ 74 | 1,860 ~ 12,805 | 数据齐全 |
| 低谷 | 2026-02 | 31 | 1,860 | 春节，正常 |

单聊关系 80 个、群 65 个。其中：

- **最长连续活跃 22 个月**（一段关系从 2024 一直到现在）
- 连续 ≥3 个月的只有 **41%**
- **36 个单聊只出现过 1 个月**（45%）—— 一闪而过

### 由此得到三条硬约束

1. **不能从 2024-03 直接播**：前 17 个月几乎是一条空线，看的人会以为坏了。
   → 每一帧必须**同时输出"当月数据完整度"**（会话数），让它自己说明这一段是数据缺失、不是没聊天。
2. **不能把所有关系都画上**：36 个一闪而过的单聊会让画面在后半段剧烈抖动。
   → 设最低门槛（当月 ≥10 条才进图），并在输出里说明被过滤了多少。
3. **群的"成员变化"拿不到时间戳**：`contact.db` 的 `chatroom_member` 只有**当前**成员，没有"谁何时进群"。
   → 拓扑变化只能**从发言推断**：本月在这个群说过话 = 本月活跃成员。文档、代码、输出都要写清楚这是推断，不是成员名单。

---

## 3. 数据模型

### 帧

一帧 = 一个自然月。字段：

| 字段 | 含义 | 来源 |
|---|---|---|
| `month` | `YYYY-MM` | `create_time` |
| `messages` | 当月消息总数 | 计数 |
| `talkers` | 当月有消息的会话数 | `distinct talker` |
| `people` | 当月发过言的人数 | `real_sender_id` → `Name2Id` |
| `completeness` | **数据完整度标记** | 会话数 ≥ 20 记 `full`，否则 `sparse` |
| `edges` | 当月的边（见下） | 聚合 |

### 节点

| 类型 | 定义 | 大小由什么决定 |
|---|---|---|
| 人 | 发过言的 `real_sender_id` | 当月发言条数 |
| 群 | `@chatroom` 会话 | 当月消息条数 |

### 边

| 边 | 含义 | 权重 |
|---|---|---|
| 人—人 | 两人在**同一个群**里都发过言（弱关系） | 共现次数 |
| 我—人 | 单聊有消息（强关系） | 当月消息条数 |
| 群—人 | 这个人在这个群说过话（**推断的活跃成员**） | 当月发言条数 |

**边权只叫「互动量」，不叫「亲密度」。** 和同事一天 50 条是工作，和家人一周 3 条是亲近。
除非把「主动发起比例 / 回复延迟 / 深夜时段」也算进去，但那需要单独校准，不在这一期。

---

## 4. 每月的边状态

每帧给每条边打一个状态，这是动画的"颜色"来源：

| 状态 | 判据 |
|---|---|
| `new` | 上月没有这条边，本月出现 |
| `stable` | 连续 ≥3 个月存在 |
| `fading` | 存在，但权重比上上个月降 ≥50% |
| `gone` | 上月有，本月没有 |

**`gone` 是最重要的产出**——"和某人最后一次说话是 2025-12，之后再没出现过"。

---

## 5. 分两期

### 一期：文本版（CLI）

```
weflow-cli replay [--months 6] [--min-weight 10] [--json]
```

输出形态：

```
2025-09  full    消息 4,748 · 会话 47 · 发言者 190
  新出现 12 条关系（例：联系人A、联系人B…）
  断掉   3 条关系（例：联系人C 最后一句「改天聊」）
2025-10  full    消息 6,751 · 会话 45 · 发言者 189
  …
```

**先做它的理由**：数字对了、断边捞得出来了，动画才有意义。如果数据显示"其实没什么断的"，二期直接砍掉。

### 二期：HTML 动画

单文件、无外部依赖、离线可开。三条轨道：

1. 主画布：关系网络逐月生长（边按状态着色，`gone` 留一道残影后消失）
2. 右侧：消息量 / 会话数 曲线，播放头随时间走
3. 底部：当月高频词（取自已有的 `.articles.json` 与消息文本，不调模型）

按「播放」逐帧推进，可拖时间轴、可单月步进。

## 6. 验收标准（可验，不是"看着差不多"）

| 编号 | 检查 | 判据 |
|---|---|---|
| A1 | 帧数守恒 | `--json` 的帧数 == 库里出现的月数 |
| A2 | 消息数守恒 | 各帧 `messages` 之和 == 全库消息总数（误差 0） |
| A3 | 完整度标记正确 | 2025-08 必须 `sparse`，2025-09 必须 `full` |
| A4 | 断边可复现 | 任取一条 `gone`，用它两个月的原始消息能手算出来 |
| A5 | 过滤有交代 | 被 `--min-weight` 过滤掉的边数要打印出来，不许静默丢 |
| A6 | 不联网 | 全程无出网请求（纯本地读取） |

A2 是关键——它对不上就说明有分片没读到，那个"关系消失了"可能是假象。

---

## 7. 不做的事（明确划掉）

- **不做"亲密度"**：只输出互动量，命名就叫 `interactions`。
- **不做"谁什么时候进群"**：没有时间戳，不猜。
- **不做增量/实时**：一次全量扫描，30 秒内跑完即可，不做缓存。
- **不接 AI**：这一期的卖点是"数据自己长出来的形状"，加模型只会让人怀疑画的东西是编的。

---

## 8. 工作量

| 期 | 内容 | 预计 |
|---|---|---|
| 一期 | 扫描 + 按月聚合 + 断边检测 + CLI + 测试（A1–A6） | 2–3 小时 |
| 二期 | 单文件 HTML + 帧数据内嵌 + 播放控件 | 3–4 小时 |

一期风险最高的是 **A2 守恒**：现有代码里消息读取有"某分片读不了"的分支，如果扫的时候有分片失败，总数会少于真实值，而断边看起来就像真断了。所以一期**必须先做守恒检查，再输出任何结论**。
